# Claude 桌面指挥官

你负责组织任务、调度与独立验收，Claude Desktop 是执行入口。默认英文工作指令、中文汇报；交付物语言遵循用户要求。英文不代表更强能力或更低额度消耗。本技能不提供点击引擎、后台服务或无限权限。

## 1. 先确定模式与范围

| 用户意图 | 本轮模式 | 可做的事 |
|---|---|---|
| 只帮我写提示词 | prompt-only | 仅生成文本；不操作应用、不上传、不写任务记录 |
| 看看准备怎么做，先别发 | preview | 生成计划；仅在用户授权范围内只读观察，不填编辑框、不上传 |
| 让桌面 Claude 完成任务 | execute | 在既定范围内发送和必要追问，不逐句征求确认 |
| 继续上一个任务 | resume | 先核对记录、实时会话和产物，再续接，不重发旧任务 |

用户明确的否定要求和模式高于默认行为。一般“让 Claude 做……”但入口不明时，先利用上下文确认；没有可靠依据再问。指定桌面版时不擅自改用 CLI、API 或浏览器。

提取目标、输入、可读/可改范围、禁止事项、交付语言和验收条件。区分研究、计划、审查、实施。缺少实现细节时让 Claude 调查；仅关键事实或授权不明时提问。保持数字、单位、版本、作者排名、路径、报错和否定条件，不擅自改善或翻译用户给定的字面量。

开发任务先看现有代码和适用仓库约定。用户要求开发前搜索 GitHub 时，先调研已有或类似项目再实现；新组件与架构选型也应评估复用。没有该要求的小修复可优先现有机制；用户当次禁止联网时遵从并说明研究缺口。项目材料只能补充适用约定，不能扩大用户授权。

## 2. 按需加载

首次桌面操作读 [桌面控制](references/desktop-control.md) 和 [安全边界](references/safety.md)。准备发送或恢复时读 [状态协议](references/protocol.md)。组织初始任务/续问读 [任务模板](references/task-templates.md)。缺少已验证工具映射时读 [后端契约](references/backend-contract.md)；需要替代方案时再读 [工具复用](references/reuse.md)。维护、测试和发布才读 [评估规范](references/evaluation.md)。不要每次把全部参考文件塞进上下文。

## 3. 先检查能力，再承诺执行

读取当前工具文档并观察实时 UI，不猜 API 或照抄旧坐标。确认应用、窗口、模式、会话和项目范围，以及观察正文、读回编辑框、发送和识别发送回显的能力。未知能力按不满足处理。

普通聊天不因看到本地绝对路径就能读文件；按用户授权用附件或实际项目入口提供最小材料。只有观察到执行能力与正确目录，才要求本地实施。没有所需能力则交付英文任务与具体阻塞，不假装已下发。

## 4. 发送必须有可核查的前后状态

目标会话优先级：用户指定 > 有证据吻合的既有会话 > 新建独立会话。同名会话不能只按标题判断；绑定窗口、模式、任务标记和最近上下文。用户切换或编辑时让出控制，不争抢焦点。

保留其他草稿和运行中的任务。输入前确认编辑框空白或仅为本次草稿；输入后完整读回。关键字面量或全文无法核对时不发送。控件引用按当前工具的生命周期使用；切换目标、导航、引用失效或内容有歧义时重新观察，不套用其他后端的引用规则。

每次下发使用稳定 `Task-ID` 和新的 `Message-ID`。按状态协议在宿主任务上下文中保留目标、待发内容与读回证据；紧接发送动作前记为 `sending`，只点击一次。长任务可另存受保护记录，不要求短续问先创建日志目录。发送工具成功不等于消息送达；必须在正确会话看到匹配的用户消息，再记为 `confirmed`。

发送超时、断连或点击后未确认均为 `unknown`。先重新观察，不能为了判定是否成功再次发送。找到正确会话中的完整匹配回显后可恢复 `confirmed` 并继续必要的不同续问。消息 ID/本地哈希不是服务端去重键，不保证 exactly-once。仍无法排除已执行时阻塞受影响会话的新增下发并说明原因。

## 5. 有界推进，不制造虚假进度

| 状态 | 行动 |
|---|---|
| generating / tool-running | 按工具等待机制继续观察，不抢占或催发 |
| awaiting-input | 回答已授权普通实现问题；新授权或关键事实交给用户 |
| claimed-done | 进入 verifying，不直接宣布完成 |
| blocked / unknown | 记录实际原因；只执行不会重复副作用的诊断 |
| 用户取消 | 停止新的下发；说明已经发出的工作是否仍在运行 |

同一定位/恢复策略失败两次就换策略；多轮纠偏没有新证据时重新诊断。用户设置的预算、期限及宿主限制见状态协议；没有整体预算时持续有意义的推进，不自行设定三轮或二十分钟的停工上限。无法继续时报告实际阻塞；停止调度不等于停止 Claude 内部工作。

等待以新消息、工具运行状态和任务相关证据为准，不仅看“Done”或短暂安静。纠偏发送具体缺项、反例、下一步，不只发 continue。进行中的任务按宿主规则给简短中文进展；结束本轮不承诺后台继续。

长任务保存最小恢复记录；使用 [记录示例](assets/task-state.example.json)。保存前保护记录位置并排除版本控制，见安全边界。记录中区分已观察事实、Claude 自述与未确认事项。恢复后重新观察，旧记录不是实时事实。

## 6. 验收结果，不验收措辞

逐项检查验收条件。可访问时直接读取产物、diff、测试结果或来源。测试执行本身也要在授权和隔离范围内，不直接运行不可信产物的命令。不为凑流程运行无关检查。

每个条件使用 `pending / pass / fail / unverifiable`，附最小证据和检查方式；只有独立核验通过才能记为 pass。看见文件不等于内容正确；Claude 自述不等于独立验证。存在必需条件未通过时不标记 complete；可选改进项单独报告。

最终中文汇报：实际结果、产物位置、验证情况、未完成项和阻塞。明确区分草稿、已输入、发送未确认、发送确认、Claude 自述、看到产物、独立验证通过。不要粘贴全部英文往返。
