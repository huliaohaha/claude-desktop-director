# 后端能力契约

这是语义契约，不是可直接调用的统一 API。实际函数名、参数和错误类型必须从已安装工具文档取得。候选版未附可执行 Peekaboo/MCP 驱动，不宣称这些映射已端到端验证。

| 语义能力 | 必要观察结果 | 缺少时 |
|---|---|---|
| identify_target | 应用/窗口、模式、会话锚点、项目范围 | 不写入 |
| observe | 新观察、时间、正文/控件、截断标记 | 不操作旧引用 |
| read_composer | 完整文本与可核对内容 | 不发送 |
| input_text | 只写正确编辑框，不覆盖外来草稿 | 只提供提示词 |
| send_once | 对当前发送控件执行一次动作，返回实际错误 | 结果不明按 unknown |
| observe_echo | 正确会话内完整匹配的用户消息 | 保持 unknown |
| read_artifact | 已授权产物与检查证据 | 条件 unverifiable |

Freshness：不要把截图和 AX 数据当原子同一时刻；二者冲突则复查。原生后端如支持窗口绑定/快照绑定，优先启用。只有语义控件无法定位时才用新截图相对窗口坐标，且必须可验证目标。

每个可发布适配写清：后端/版本、macOS、Claude Desktop 版本、模式、能力缺口、经过哪些真实用例。仅有文档映射应标 `documented-not-tested`，不能标 supported。

建议先完成一条现有原生工具链的真实验证，或评估 Peekaboo；不同时安装多个后端，也不自动打开远程调试/内部网络接口。
