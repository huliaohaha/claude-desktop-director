# 桌面控制：观察、操作、再观察

## 启动检查

使用宿主已有工具，不自动安装新后端。先读取实际工具文档；不要把某宿主的 `mcp__cua_repl.js` 或某次 `cua.getApp` 示例当通用 API。可用界面能力由当前工具与已授权权限决定。

记录 macOS、Claude Desktop、宿主和后端版本，判断是否只读预览。选择用户指定应用/窗口；多窗口时固定窗口身份，不能只选“最前面的 Claude”。获取当前模式、会话标识/可见标题、任务标记、工作目录、编辑框和最新消息。不得读取应用私有数据库、cookies、令牌或 Keychain 来补齐识别。

执行前确认：正文观察、编辑框完整读回、目标绑定、安全文本输入、发送动作、发送回显识别均可用。截图可以辅助，但不能把局部截图当长文本完整校验。能力不足时降级为提示词/只读报告。

## 输入与发送

1. 重新观察目标；用户正在输入、目标变更、其他任务生成或有无关草稿时暂停，不清空内容。
2. 保留原始字面量。优先文本设置/粘贴；不得未经确认宣称剪贴板已恢复。剪贴板保留能力不明时，告知实际影响或换工具。
3. 完整读回编辑框。检测截断、格式改变、附件折叠和路径/单位/否定词丢失。无法读回就不发送。
4. 发送控件引用须仍属于当前目标与可用观察。按宿主文档处理引用生命周期；不能假设所有工具在每次滚动或快照后都使引用失效。页面导航、目标切换、失效报错或歧义后重新观察。截图与 AX 读数不一致时复查，不通过重做动作“试一下”。
5. 先记录 sending，再执行一次发送；按状态协议判定 confirmed 或 unknown。
6. 确认消息进入正确会话，不仅检查编辑框变空或出现 spinner。立即生成完成也可能没有可见 spinner。

长文本优先减少无关背景。附件需要核实上传完成、文件名和可读取性；这是材料外发，仍受授权约束。分块仅用于无法用附件且确有必要的情况，注明 Context i/N 并重复范围限制；“最后一块前不要执行”只是一条提示，不是执行屏障。高影响任务不要靠分块提示实现原子执行。

## 运行中

使用工具提供的等待/轮询机制；有事件能力先用事件。无事件能力可逐步增加观察间隔，例如 2、5、10、20 秒，最大不超过宿主本轮允许的等待时间；这些数值是候选默认值，不是实测最佳值。新消息后恢复较短间隔，不反复读取全历史。

区分生成、工具工作、等待批准、错误和完成自述。生成停了只代表可以检查，不代表产物通过验收。会话滚动和侧栏滚动分别定位。出现截断时保留最后完整结果，再定向取缺项。

## 异常与取消

点击/发送/附件上传超时后先判断副作用是否发生；可能发生则按 unknown 处理，不重试该副作用。只读观察失败可以有限重试。限额、登录、连接或系统权限阻塞时报告可见事实，不更改账户、订阅、模型、网络或权限策略。

用户要求取消时停止新增消息。已有生成是否停止需观察；只有用户取消范围与当前工具允许时才使用当前任务的停止按钮，不影响其他窗口。取消调度不等于撤回已执行修改，不自动回滚、不杀其他进程。

## 恢复

读取最小记录，重新确认会话、目录和产物。窗口 ID 或截图编号不是持久会话 ID；应用重启后必须重新定位。消息标记也是待核对数据，不独立证明会话归属。记录显示 sending/unknown 时，只观察或请求接管；不能直接补发。
